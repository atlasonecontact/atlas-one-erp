┌─────────────────────────────────────────────────────────────────────┐
│ PASO 1: Crear el Bot de Telegram                                    │
└─────────────────────────────────────────────────────────────────────┘

  1. Abrir Telegram
  2. Buscar: @BotFather
  3. Enviar: /newbot
  4. Responder:
     • Nombre del bot: Atlas One ERP Bot
     • Username: AtlasOneERP_bot
  5. Copiar el TOKEN que te da BotFather
     Ejemplo: 1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

┌─────────────────────────────────────────────────────────────────────┐
│ PASO 2: Configurar Variables de Entorno                             │
└─────────────────────────────────────────────────────────────────────┘

  1. Crear archivo .env.local en la raíz del proyecto
  2. Agregar:

     NEXT_PUBLIC_SUPABASE_URL=https://tu-proyecto.supabase.co
     NEXT_PUBLIC_SUPABASE_ANON_KEY=tu-anon-key
     TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

┌─────────────────────────────────────────────────────────────────────┐
│ PASO 3: Ejecutar Script de Base de Datos                            │
└─────────────────────────────────────────────────────────────────────┘

  1. Ir a Supabase → SQL Editor
  2. Ejecutar: scripts/202_fix_demo_complete.sql
  3. Verificar que NO hay errores

┌─────────────────────────────────────────────────────────────────────┐
│ PASO 4: Reiniciar la Aplicación                                     │
└─────────────────────────────────────────────────────────────────────┘

  npm run dev

 PARTE 3: VERIFICACIÓN

┌─────────────────────────────────────────────────────────────────────┐
│ Verificar en Base de Datos                                          │
└─────────────────────────────────────────────────────────────────────┘

  Ejecutar en Supabase SQL Editor:

  SELECT 
    '✅ ESTADO TELEGRAM' as titulo,
    u.email,
    nc.telegram_chat_id,
    CASE WHEN nc.telegram_enabled THEN '✅' ELSE '❌' END as habilitado,
    CASE WHEN nc.telegram_verified THEN '✅' ELSE '⚠️' END as verificado
  FROM auth.users u
  LEFT JOIN kioscos k ON k.owner_id = u.id
  LEFT JOIN notification_configs nc ON nc.kiosko_id = k.id
  WHERE u.email LIKE 'demo.%@atlasone.com'
  ORDER BY u.email;

 TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│ ❌ No llegan notificaciones                                          │
└─────────────────────────────────────────────────────────────────────┘

  1. Verificar TELEGRAM_BOT_TOKEN en .env.local
  2. Verificar que el usuario inició el bot (/start)
  3. Verificar Chat ID correcto en notification_configs
  4. Probar bot manualmente:

     curl -X POST "https://api.telegram.org/bot<TOKEN>/sendMessage" \
       -H "Content-Type: application/json" \
       -d '{"chat_id":"<CHAT_ID>","text":"Test"}'

┌─────────────────────────────────────────────────────────────────────┐
│ ❌ Todos reciben las mismas notificaciones                           │
└─────────────────────────────────────────────────────────────────────┘

  Problema: Todos tienen el mismo Chat ID

  Solución:
    1. Cada usuario debe obtener SU PROPIO Chat ID (@userinfobot)
    2. Cada usuario debe configurar SU Chat ID en el dashboard
    3. Verificar en SQL que cada kiosko tiene un Chat ID diferente

┌─────────────────────────────────────────────────────────────────────┐
│ ❌ "Chat not found" al probar                                        │
└─────────────────────────────────────────────────────────────────────┘

  1. Iniciar el bot: @AtlasOneERP_bot → /start
  2. Verificar que el Chat ID es correcto
  3. El bot debe estar activo (verificar con @BotFather)
